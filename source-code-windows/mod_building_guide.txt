GEOCHEATS / DASH MOD BUILDING GUIDE - v1

LINKING AND SIMPLE UI
A saved valid game link is reused on startup; otherwise Steam's standard install,
appmanifest_322170.acf and libraryfolders.vdf are searched automatically. Both
GeometryDash.app and Geometry Dash.app are recognized on macOS. The .app bundle's
CFBundleExecutable is resolved with macOS plutil, including binary Info.plist.
When no install is found, Choose file opens a native OS file chooser. Successful
linking hides the chooser and shows the same controls as automatic linking.
Linking and saving an enabled switch do not require a running game. The actual
memory mod can take effect only after a compatible game process starts.
The native windows contain no slogan, browser UI, WebView or local web server.
The only HTTP client remaining is a one-time upgrade helper that can gracefully
stop an older browser-based GeoCheats controller; it serves no network API.
The Mac ZIP contains only GeoCheats.app and Dash.app. Helper CLI, icons, notices,
compatibility details and signing status live inside Contents/Resources (documents/icons) and Contents/Helpers (CLI).
Dash's main screen is a small patch form; Advanced JSON is optional.


NATIVE DESKTOP UPDATE (1.3.0)
Dash now includes a graphical recipe builder in addition to its original CLI.
Both GeoCheats and Dash use the supplied logos in ICNS/ICO/Linux PNG formats.
The GUI can inspect a game, generate a single-patch draft, verify a complete
JSON recipe, discover the experimental Intel Mac profile, and download .dash.
The CLI remains available for automated scripts and AI-driven authoring.
Windows: Dash.exe is the GUI; Dash-CLI.exe is the CLI. EXE icons require
packaging/build-windows.sh (windres generates linked .syso resources).
macOS: GeoCheats.app and Dash.app are universal app bundles in ZIP and DMG.
The CLI is Dash.app/Contents/Helpers/dash. packaging/build-macos.sh builds on
macOS, signs the full bundles, validates signatures/icons, and launches both
apps through LaunchServices before and after ZIP extraction. Without Developer
ID secrets these are ad-hoc signed, not notarized; see packaging/SIGNING.md.
Linux: geocheats-dash is the CLI; geocheats-dash-builder is the GUI. Both app
launchers use registered hicolor icons. DEB/RPM package payloads are checked.
Packaging checks do not extend native game compatibility or prove gameplay.

START HERE
GeoCheats and Dash use native desktop windows, not browser or WebView controls.
The binaries include their runtime. Users do not install Go, Python, Node,
Geode or Scoop. Operating-system graphics libraries are still required.
Source builders need Go 1.24+, CGO and a C compiler. Build dependency purego is
compiled into relevant platforms; it is not a separate user installation.

Linking only inspects an installed executable and stores its path. It does
not launch or modify the game. Connect attaches separately to a running game.
Paths use the current account's configuration directory and Steam library
discovery. No username or uploaded-file workspace path is embedded.

CURRENT SUPPORT
Windows AMD64: native process-memory backend and seven bundled recipes for
the exact GD 2.2091 executable below. The earlier invincibility patch was
confirmed by the user. New modes are experimental and need gameplay tests.
Linux AMD64: Windows game under Proton/Wine, same executable fingerprint.
Native Linux attachment depends on the user's existing ptrace permissions;
GeoCheats does not weaken them. X11 global hotkeys require libX11 and an EWMH
window manager; Wayland global hotkeys are unavailable. UI actions remain.
macOS Intel/Apple Silicon: app, linking, inspection and Dash are built.
A Mach task-memory backend is implemented; native CI exercises self-process
lookup, memory reads, writes and restoration. External game access is unverified.
The seven bundled recipes target Windows/Proton, not native Mac. An experimental
Intel Mac invincibility recipe is generated locally when the exact death-handler
symbol and supported frame prologue exist in the linked game's symbol table.
Missing symbols/prologues are refused. Other six modes need native Mac profiles.
ARM64 code patching is blocked pending instruction-cache support. Universal
Mach-O inspection is available; universal slice patching is not implemented.
Do not claim all platforms have gameplay support based on compilation alone.

USAGE
Run the binary matching your OS/CPU; keep it running while playing.
Link the installed executable, launch the game yourself if desired, Connect,
then enable mods. Switches start OFF only on a fresh profile, then remain saved
until disabled. You may enable compatible switches while the game is closed;
the controller reconnects every two seconds and restores saved choices. Closing
the GeoCheats window hides it; the controller keeps running. Reopen it from
the tray/menu-bar icon or by launching the native app again.
Quit restores runtime patches but remembers switches for next launch/login.
On first enable, Start GeoCheats at login is installed and can be disabled in
the UI. Keep the executable/app at a stable path. No game file is edited on disk.

PERSISTENCE / CRASH RECOVERY
settings.json and settings.backup.json in the current account's GeoCheats config
directory store enabled ID->executable SHA-256 and login-start preferences.
Each copy is atomically replaced; a damaged primary recovers from its backup.
Missing/different mod hashes are never applied to a newly updated game.
Restore & disconnect pauses automatic connection until Connect or a switch change.
User login entries: Windows HKCU Run/GeoCheats; macOS user LaunchAgents/
io.geocheats.controller.plist; Linux XDG autostart/geocheats.desktop. They run
--background with a tray/menu-bar icon and are removable. No driver is installed.
Existing controllers are protected by an OS lock/mutex and reopen their local UI.

Resume verifies exact disk hashes, guards, original/replacement bytes and overlap
before adopting a fully applied remembered code patch after a crash. Partial or
foreign patches are refused. Recovered completion gates are restored immediately;
the completion switch only rearms the hotkey. Speed baselines are saved before
write, then reconciled on matching PID/base/hash and live layer/player/value
checks, avoiding a second multiplication after controller restart. Restart the
game if any recovery check fails. Physics modes still need the controller alive.
No software can preserve preferences after its settings are deleted, or keep
running after the OS stops it without another launch. Login entries resume next
session; they are not a promise of unattended recovery from every crash/repair.

EXPERIMENTAL INTEL MAC DISCOVERY
Dash mac-profile GAME OUT.dash reads the local Mach-O symbol table. Required
symbol: __ZN9PlayLayer13destroyPlayerEP12PlayerObjectP10GameObject. It must uniquely
resolve inside __text, with Intel entry 55 48 89 e5. The recipe changes 55 to c3,
guards the following 15 bytes and pins the whole executable SHA-256. No public
address is guessed, no Geode runtime is loaded and no ARM64 patch is emitted.
Synthetic recipe tests and native self-memory tests are provided; real native
Geometry Dash gameplay tests remain needed.

MODS
Invincibility: early return from player-death routine. Solid physics remain.
High Jump: detects ordinary cube jump starts and boosts vertical velocity
2.2 times. Does not claim every form has a jump-height boost.
Super Fast / Super Slow: player movement speed x4 / x0.25, not global time.
No Jump: changes the primary-input branch; pads/triggers still move players.
Fly: holds vertical velocity at zero; W/Space/Up rises, S/Down descends.
Flight UI hold buttons work without global key capture. Physics can still
interact with this experimental effect. It does not imply invincibility.
Instant Complete: arm it, press C+G+D simultaneously (or the UI action).
For 500 ms it forces the game's normal end-portal comparisons to pass.
The game then runs its ending sequence. Levels without a standard end portal
are rejected; this is not a universal platformer-completion implementation.
Conflicting vertical modes and conflicting speed modes cannot be combined.
These mods do not block completion/achievement saving. Use offline practice.

DASH COMMANDS
dash inspect PATH_TO_GAME
dash read PATH_TO_GAME 0x512390 29
dash scan PATH_TO_GAME "48 8B C4 48 89 58 18 55"
dash export-mods OUTPUT_DIRECTORY
dash validate PATH_TO_GAME MOD.dash
dash build --game PATH_TO_GAME --recipe recipe.json --out MOD.dash
dash make --game PATH_TO_GAME --id author.name --name "Name" --rva 0x1234
          --expected "AA BB" --replace "CC DD" --out MOD.dash
Quote file paths with spaces. Dash refuses to overwrite existing outputs.
Dash does not find function meaning automatically. Scan returns candidates,
not verified hooks. Inspect/disassemble and test behavior before publishing.

SCHEMA 2
A .dash is UTF-8 JSON. Required fields: schema=2, id, name, description,
targetSha256 (64 hex digits), format (pe or macho), arch (amd64 or arm64),
kind (patch, field or hotkey), status. Optional group defines conflicts.
guards: array of {rva:"0xHEX", expectedHex:"AA BB ..."}.
patches: array of {rva:"0xHEX", expectedHex:"AA",replacementHex:"BB"}.
All RVAs are hexadecimal module-relative virtual addresses, not file offsets.
PE module base is ASLR-adjusted. Thin Mach-O offsets are relative to __TEXT.
Patch expected/replacement byte lengths must match, from 1 to 256 bytes.
Guards are 4 to 256 bytes. Fingerprints must match the exact executable.
Recipe targetSha256="AUTO" is accepted by Dash build only: it replaces AUTO
with the inspected hash after verifying expected bytes. This does NOT prove
that the recipe has correct function semantics or gameplay compatibility.

For field kind: effect is speed, high-jump or fly; speed factor is 0.1..5.
Field effects currently require the exact built-in Windows pointer profile.
Do not point these recipes at arbitrary versions or native Mac game images.
Hotkey kind uses patches temporarily; this release's trigger handler is
specifically the known Windows end-portal profile, not a general script API.
Recipes contain data, not DLLs or Geode packages. Legacy schema 1 is not
accepted by this new engine; recreate it using schema 2 or bundled recipes.

VERIFIED WINDOWS PROFILE
SHA256 4eee06d5c2e2213b4ba2b1f6233dd426bbdd0e9b29d7c375e499516b6f8f69d5
GameManager global pointer RVA 0x90bfd0; PlayLayer field +0x230.
PlayLayer vtable RVA 0x7d59b8; PlayerObject vtable RVA 0x7d47c8.
Players: PlayLayer +0xdb8 and +0xdc0.
Player vertical velocity: double +0x9a8. Speed: float +0x9fc.
Ship..spider mode flags +0x9c0..0x9c5, gravity inversion +0x9c7,
ground flag +0x9c9. Death handler RVA 0x512390, first byte 48 -> C3.
Primary input comparison immediate RVA 0x4f625d, 01 -> 7F.
End-check branch RVA 0x513eb7, 73 -> EB; reverse comparison RVA
0x513ef1, 0F821B010000 -> 909090909090. End portal field +0x3320;
ending-started flag +0x3a28. These offsets are specific to this exact image.

AUTHOR WORKFLOW
1. Obtain the target's own executable and inspect it with Dash.
2. Identify functions/fields with a disassembler; retain evidence and original
   bytes. Respect calling conventions, ASLR and instruction boundaries.
3. Write a patch recipe with exact bytes and sufficient independent guards.
4. Run Dash build and validate. Test with a disposable/offline game session.
5. Check enabled behavior, OFF restoration, normal exit, forced game exit,
   level restart, dual players, mode changes, portals and mod conflicts.
6. Test the actual OS backend. A cross-build is not a runtime test.
7. Publish only truthful compatibility/test status. Future updates require
   analysis again. Do not guess offsets or wildcard the executable hash.

BUILD / GITHUB
go test ./...
go build -o GeoCheats ./cmd/geocheats
go build -o Dash ./cmd/dash
Desktop GUI builds require CGO_ENABLED=1 and native graphics build libraries.
The standalone Dash CLI still supports CGO_ENABLED=0. Use the platform packaging
scripts for correctly embedded icons and native app bundles.
See .github/workflows/build.yml for cross-platform build artifacts.
No repository is created or uploaded automatically by this source package.

LIMITATIONS / HANDOFF
The native Mac executable has not been analyzed here. Experimental Intel symbol
discovery is available; native field profiles, universal game slices and ARM64
cache synchronization are outstanding. Backend OS permission failures
are surfaced, not bypassed. Linux/Wayland keys require UI controls.
Browser UI and native memory APIs need platform testing. The game EXE must
never be committed or redistributed in the repository.
